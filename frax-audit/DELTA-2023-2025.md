## 4. Per-file change summary (v3 rewrite, `f474378`, unless noted)

### Core pair logic

**`FraxlendPairCore.sol` (905 lines changed) — rewrite.**
- **Oracle model replaced.** Baseline read two Chainlink feeds directly
  (`oracleMultiply`/`oracleDivide` + `oracleNormalization`, single
  `exchangeRate`, `PriceTooLarge` cap). HEAD reads one dual oracle via
  `IDualOracle.getPrices()` returning `(isBadData, low, high)`; stores
  `lowExchangeRate`/`highExchangeRate`; borrow paths check the deviation
  (`(high-low)/high <= maxOracleDeviation`, else `ExceedsMaxOracleDeviation`);
  a bad-oracle read emits `WarnOracleData` instead of reverting. Solvency
  checks use the **high** rate (`isSolvent` modifier); liquidations use the
  **low** rate. `_isSolvent` math itself is byte-identical.
- **Interest engine rewritten.** Baseline `_addInterest` used the v1
  `IRateCalculator.getNewRate(abi.encode(...), rateInitCallData)`, applied a
  `penaltyRate` past `maturityDate`, and reset the rate to `DEFAULT_INT` when
  unborrowed/paused. HEAD splits into `_calculateInterest` (view) +
  `_addInterest`, uses `IRateCalculatorV2.getNewRate(deltaTime, utilization,
  fullUtilizationRate)` returning `(newRate, newFullUtilizationRate)`,
  short-circuits when interest is paused, and guards the accrual with
  `uint128` overflow checks. `previewAddInterest()` added. **Maturity and
  penalty rate removed entirely** (0 mentions at HEAD vs 14 at baseline).
- **ERC-4626 surface completed.** Added `mint`, `withdraw`,
  `previewDeposit`, `previewMint`, `previewRedeem`, `previewWithdraw`
  (baseline had only `deposit`/`redeem`).
- **Borrower/lender whitelists removed.** `borrowerWhitelistActive`,
  `lenderWhitelistActive`, `approvedBorrowers`/`approvedLenders` mappings,
  `approvedBorrower`/`approvedLender` modifiers, and `isNotPastMaturity`
  are all gone; `deposit`/`borrowAsset`/`liquidate` no longer carry them.
- **Constructor-only deployment.** Baseline `initialize()` + immutables set
  partly post-deploy are gone; all settings come from the constructor
  (`_configData`/`_immutables`/`_customConfigData`).
- **`CurrentRateInfo` repacked**: `lastBlock`/`feeToProtocolRate` narrowed to
  `uint32`, `fullUtilizationRate` (`uint64`) added. `ExchangeRateInfo`
  repacked: `lastTimestamp` widened to `uint184`, oracle address +
  `maxOracleDeviation` now stored in-struct.
- New `protocolLiquidationFee` (in addition to clean/dirty fees); `maxLTV`
  and liquidation fees changed from `immutable` to mutable (see
  `FraxlendPair.sol` setters).

**`FraxlendPair.sol` (669 lines changed) — rewrite.**
- View helpers inlined from the deleted `FraxlendPairHelper` (`getConstants`,
  `getUserSnapshot`, `getPairAccounting`, `toBorrowShares/Amount`,
  `toAssetShares/Amount`).
- ERC-4626 views added: `convertToAssets`, `convertToShares`,
  `pricePerShare`, `totalAssets`, `maxDeposit`, `maxMint`, `maxWithdraw`,
  `maxRedeem`.
- **Mutable risk parameters with one-way revocation:** `setOracle`,
  `setMaxLTV`, `setRateContract`, `setLiquidationFees`, each paired with a
  `revoke*Setter` (guarded by `SetterRevoked`). Baseline had none of these
  (params were immutable).
- **Granular pauses/limits** (delegating to `FraxlendPairAccessControl`):
  `pauseBorrow`/`setBorrowLimit`/`revokeBorrowLimitAccessControl`,
  `pauseDeposit`/`setDepositLimit`/`revokeDepositLimitAccessControl`,
  `pauseRepay`/`pauseWithdraw`/`pauseLiquidate`/`pauseInterest` + revokes.
  Baseline had only global `pause()`/`unpause()`.
- Removed: `setTimeLock`, `setApprovedLenders`, `setApprovedBorrowers`.
  `changeFee` lost its `whenNotPaused` guard. `withdrawFees` now also
  returns/transfers a collateral amount (event gains `collateralAmount`).

**`FraxlendPairAccessControl.sol` (NEW, 218 lines).** Extracted access-control
layer: `Ownable2Step` + `Timelock2Step` base; internal `_setBorrowLimit`,
`_setDepositLimit`, `_pauseRepay/Withdraw/Liquidate/Interest` with matching
`_revoke*` one-way revocations; circuit-breaker setter. Pause state is now
per-function (`isBorrowPaused`, `isDepositPaused`, `isRepayPaused`,
`isWithdrawPaused`, `isLiquidatePaused`, `isInterestPaused`) plus
`borrowLimit`/`depositLimit` caps.

**`FraxlendPairAccessControlErrors.sol` (NEW, 37 lines).** Errors for the
above (`AccessControlRevoked`, `BorrowPaused`, `ExceedsBorrowLimit`,
`ExceedsDepositLimit`, `InterestPaused`, `LiquidatePaused`, `RepayPaused`,
`WithdrawPaused`, `OnlyProtocolOrOwner`, `OnlyTimelockOrOwner`, …).

**`FraxlendPairConstants.sol` (38 lines).** Constants changed
`internal` → `public`; added `DEVIATION_PRECISION` (1e5) and
`RATE_PRECISION` (1e18); removed `DEFAULT_INT`/`DEFAULT_PROTOCOL_FEE`.
Errors removed: `OnlyApprovedBorrowers/Lenders`, `PastMaturity`,
`ProtocolOrOwnerOnly`, `OracleLTEZero`, `NotOnWhitelist`, `NotDeployer`,
`NameEmpty`, `AlreadyInitialized`, `BorrowerWhitelistRequired`,
`OnlyTimeLock`, `PriceTooLarge`. Errors added: `SetterRevoked`,

**`FraxlendPairDeployer.sol` (510 lines changed) — rewrite.**

  deployer now calls `registry.addPair()`. `getAllPairAddresses` delegates.

**`FraxlendWhitelist.sol` (58 lines) — slimmed.** Oracle whitelist and rate

**`FraxlendPairHelper.sol` (DELETED, 298 lines).** Read-only helper

### Rate calculators

**`VariableInterestRate.sol` (190 lines) — full rewrite.** Baseline was a
stateless `pure` calculator implementing v1 `IRateCalculator`
(`getNewRate(bytes _data, bytes _initData)` + `getConstants` +
`requireValidInitData`). HEAD implements `IRateCalculatorV2` with
constructor-configured immutable parameters (`VERTEX_UTILIZATION`,
`MIN/MAX_TARGET_UTIL`, `MIN/MAX_FULL_UTIL_RATE`, `ZERO_UTIL_RATE`,
`RATE_HALF_LIFE`, `VERTEX_RATE_PERCENT`) and `getNewRate(deltaTime,
utilization, fullUtilizationRate)` + `getFullUtilizationInterest`: a kinked
utilization curve whose full-utilization rate drifts toward a target band
with exponential half-life adjustment. `name()` now returns a suffixed name;
`version()` added.

**`LinearInterestRate.sol` (6 lines).** Cosmetic only: pragma 0.8.16 →
0.8.19, named import, numeric literal underscores. Formula unchanged; still
v1 `IRateCalculator`.

## 5. The three 2025 logic changes (`f1eae68`, 2025-02-07)

These are the **only** post-v3 changes to executable pair/deployer logic:

1. **Interest-pause timestamp reset (`FraxlendPair.sol`, 2 lines).**
   `unpause()` and `pauseInterest()` now set
   `currentRateInfo.lastTimestamp = block.timestamp` (the latter only when
   unpausing interest while the pair is not paused), so no interest accrues
   over a pause period. Previously `_addInterest()` ran but the timestamp
   was left stale.
2. **Borrow-limit enforcement (`FraxlendPairCore.sol`, 3 lines).** The borrow
   path now reverts with `ExceedsBorrowLimit()` when
   `borrowLimit < totalBorrow.amount + _borrowAmount`. (The limit setter
   existed since v3; enforcement in this path was added here.)
3. **Mandatory pair seeding + SSTORE2 fixes (`FraxlendPairDeployer.sol`, ~34
   lines; deployer `version()` 4.1.0 → 5.0.0).**
   - New `amountToSeed` (settable by whitelisted deployers via
     `setAmountToSeed`); `_deploy` now reverts with `MustSeedPair()` if it is
     0, then approves and `deposit`s `amountToSeed` of the asset into the new
     pair as the deployer — i.e. every new pair is seeded at creation.
   - `setCreationCode` now zeroes `contractAddress2` when creation code is
     ≤13,000 bytes (the exact fix ToB recommended for TOB-FXLEND-8), and
     `_deploy` only concatenates the second SSTORE2 blob when
     `contractAddress2 != address(0)` (the TOB-FXLEND-7 recommendation).
     Note: the `BytesLib.slice(..., 13000)` call in `setCreationCode` still
     assumes ≥13,000 bytes for the first half — the first half of the
     TOB-FXLEND-7 recommendation was not adopted in this form.

## 6. Most security-relevant delta items (for the audit phase)

Ordered by likely audit relevance, not by severity (no severity is asserted —
groundwork only; each item needs live-deployment verification before any
finding is claimed):

1. **Dual-oracle model is entirely new since the last Fraxlend review.**
   Single-feed Chainlink reads → `IDualOracle.getPrices()` low/high pair,
   deviation-gated borrows, warn-don't-revert bad data, high-rate solvency
   vs low-rate liquidation asymmetry. The oracle contracts themselves live
   outside this repo (`frax-oracles`); only `DualOracleChainlinkUniV3` and
   the abstracts are in-repo. Any oracle-manipulation analysis must cover
   both legs and the deviation gate.
2. **Interest engine rewrite (v2 rate interface + `_calculateInterest`).**
   New rate/full-utilization state, pause-aware accrual, `uint128` overflow
   guards that silently skip accrual on overflow, and fee-share minting
   (`feesShare` computed against `totalAsset.amount - feesAmount`).
   Penalty/maturity logic — including the TOB-FXLEND-3 penalty-rate bug
   class — is gone with the maturity concept.
3. **`VariableInterestRate` rewrite.** The kinked-curve + half-life drift
   model (`getFullUtilizationInterest`) is new code with no prior review in
   this repo's history; rate bounds (`MIN/MAX_FULL_UTIL_RATE`) and vertex
   math are the core of pair pricing.
4. **ERC-4626 completion multiplies share-math paths.** `mint`/`withdraw`
   and four preview functions join `deposit`/`redeem`; rounding directions
   in `VaultAccount.toShares/toAmount` (unchanged library) now feed more
   entry points, and `convertToAssets/Shares` + `max*` views expose the
   same conversions.
5. **Borrower/lender whitelists removed; oracle/rate whitelists removed.**
   Two independent allowlist layers that existed at baseline are gone. Any
   assumption that "only approved lenders/borrowers" or "only whitelisted
   oracles/rate contracts" can interact with a pair is false at HEAD.
   Deploy-time oracle/rate validation no longer exists in-repo.
6. **Mutable risk parameters + one-way revocation.** `setOracle`,
   `setMaxLTV`, `setRateContract`, `setLiquidationFees` can change a live
   pair's pricing, leverage cap, interest model, and liquidation economics
   until revoked; revocation is per-setter and permanent. Access control
   for these setters (protocol/owner/timelock roles via
   `FraxlendPairAccessControl` + `Timelock2Step`) is new surface.
7. **Granular pauses + borrow/deposit limits.** Per-function pause flags and
   caps are new state machines; interactions (e.g. interest pause vs
   timestamp reset, §5 item 1; borrow-limit enforcement added only in 2025,
   §5 item 2) are exactly the kind of cross-flag logic that needs
   state-by-state review.
8. **Deployer rewrite + mandatory seeding (2025).** Registry extraction,
   removal of `deployCustom`, mutable infra addresses, CREATE2 salt/name
   uniqueness now split across deployer+registry, and the new
   seed-on-creation deposit (first-shares / inflation protection for new
   pairs — but only if `amountToSeed` is set sanely by a whitelisted
   deployer, and `deposit` is called by the deployer itself).
9. **`DualOracleChainlinkUniV3` bad-data fallback.** On stale/negative
   Chainlink data, `getPrices` returns the UniV3 TWAP price for *both* low
   and high — collapsing the deviation band to zero and re-allowing borrows
   on a single-source price. The hardcoded StaticOracle address and
   `TWAP_DURATION`/`maxOracleDelay` parameters are deployment-time trust
   assumptions.
10. **`withdrawFees` now moves collateral too, and `changeFee` lost its
    pause guard.** Fee accounting touches both asset shares and collateral
    balances; the fee path changed shape in v3 and was not part of any
    post-v3 review.
