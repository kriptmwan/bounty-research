## Unresolved cross-references

1. **Mint module export reachability (NOT decisive).** Deductive case that `core.create_loan`/`borrow_more`/`repay`/`FACTORY` are unreachable in the Mint deployment: they are absent from Mint's `exports:` list, and Mint defines its own same-selector functions, so dispatching both would be a selector collision the compiler rejects. Even if reachable, `core.create_loan` would `staticcall markets()` on the mint factory (no such function → revert) and `core.FACTORY()` would return the same factory address — no bug either way. A compile + ABI dump would be belt-and-braces only; not run.
2. **Vyper `@nonreentrant` lock storage mechanics (transient vs persistent slot).** Not traced at the opcode level; unneeded — the lock's *behavior* (shared across both callbacks, rejects re-entry before auth) is pinned by `test_reentrancy.py` (`test_callback_deposit_from_exchange_is_rejected_by_both_guards`, `test_callback_repay_from_exchange_is_rejected`).
3. **`max_borrowable` for `_N in 1..50`, `_p_avg > 0`, normal collateral.** Formula verified only against the identical legacy implementation and unit reasoning; no numeric differential test vs `ControllerView._max_borrowable` was run (view-only; controller health checks bound any quote error to a revert, and no divergence from legacy code was found).

## Candidates checked and killed (with the killing mechanism)

- **Stash overwrite / reuse across nested calls:** `_stash` asserts `stashed_controller == empty` (L178); `_unstash` clears all 6 fields (L191-196); transient writes roll back on revert (pinned by `test_stash_is_clear_after_a_reverted_call`); sequential same-tx reuse pinned by `ZapBatcher` tests.
- **Exchange re-entering entry points mid-swap:** `_create_loan`/`_borrow_more` reach `_stash` → `"Reentrancy"` (their first controller call, `amm()`, is `@reentrant` so it succeeds — the stash guard, not the controller lock, is load-bearing here, as the tests pin). `_repay` reverts earlier at `debt()` (controller view lock). Any pre-guard sweep/transfer rolls back atomically with the reverted subcall, including when the exchange catches the revert (pinned by `test_exchange_reentering_repay_cannot_drain_in_flight_collateral`).
- **Exchange reaching the other callback / same callback mid-flight:** shared `@nonreentrant` lock rejects before auth (pinned). Outside a flight, `_stashed_controller` rejects (stash empty → `"wrong controller"`).
- **Exchange re-entering via the stashed controller, or via a different controller:** stashed controller is pragma-locked; a different controller's callback fails the lock first and `_stashed_controller` second (pinned for the stashed-controller shape).
- **Stash/auth confusion between deposit and repay callbacks:** genuine controllers invoke a fixed callback per function; a mismatched callbacker would still need to pass the lock + stash auth, and no path lets an untrusted party choose the callback type.
- **`stashed_held` accounting:** deposit flow measures collateral delta against the post-`transfer_from` balance (controller pulls `_collateral + leverage` after the callback; dust left over is refunded — traced against controller.vy:661/694-695). Repay flow measures borrowed delta against the post-pull balance (controller pulls `cb.borrowed + wallet` after the callback — controller.vy:1047-1048/956-957). Fee-on-transfer on the inbound leg fails closed (controller pull reverts on shortfall). Donated balances cannot mask slippage (pinned by dust tests).
- **`_repay` pre-call collateral sweep stealing dust:** the sweep is required (controller asserts `cb.collateral <= xy[1]`, controller.vy:1004); flushing residual balances to the caller is the documented, test-pinned design in both directions, not a leak.
- **`_refund` incompleteness:** refunds the full balance of both market tokens to `msg.sender` after every entry path; no user-funds path uses a third token; the zap cannot hold ETH (no receive/fallback).
- **Standing `max_approve` allowances to controllers:** `tkn.max_approve` only tops up from zero; controllers pull from the zap only as `msg.sender` (zap entry points) or as `_callbacker` after a successful gated callback (controller.vy:695/908/956/1047/1051) — every pull site is preceded by `_execute_callback`, which reverts on an empty stash. No untrusted path spends the allowance.
- **`_execute_raw_call` USDT-style approve failure:** allowance to the exchange is always 0 on entry (revoke is asserted, L225; no other approver exists), so 0→`_max_spent` and `_max_spent`→0 transitions are the only ones, both USDT-compatible.
- **Raw-call to no-code / reverting exchange:** no-code is caught by the slippage check when `min_recv > 0` (pinned); `min_recv == 0` is a documented waiver and yields at worst a plain unleveraged loan (deposit) while repay is still protected by the strict-decrease check (L312). Exchange reverts propagate uncaught (pinned).
- **`_max_spent` cap bypass:** deposit cap is `_debt` (borrowed dust provably unspendable, pinned by `test_create_loan_exchange_cannot_take_more_than_d_debt`); repay cap is the user-supplied `_collateral_to_spend` enforced both by the approval and by the net-decrease sanity check (L315), which also catches allowance-ignoring tokens by reverting. The cap addition itself is excluded (eaab7f43).
- **Slippage-check bypass:** all three checks are balance-delta based on the zap's own balances; the only mid-flight actor besides the controller/AMM is the whitelisted exchange, which must deliver real output tokens to pass `min_recv` (donation = fair value, no protocol loss). No missing case found; `remaining < initial` (repay) is pinned as intended, including that wallet-only repay via the zap reverts.
- **Mint factory-type confusion:** in the Mint deployment only `admin()`/`set_exchange()` touch `core._LEND_FACTORY`, and `ILendFactory.admin()` / `IControllerFactory.admin()` share the identical `admin() → address` selector; `markets()`/`FACTORY()` are not exported (see unresolved #1). `FACTORY()` returns `_MINT_FACTORY.address`; `admin()` follows the mint factory's admin. No confusion found.
- **`max_borrowable` math:** identical to the legacy zap. `_N == 0` → division by zero revert (L112); `_N > 50` → Vyper `range() bounds check` revert (verified in codegen); `_p_avg == 0` → division by zero revert (L152); non-positive denominator → underflow/div-zero revert; `decimals > 18` → revert in `convert(18 - decimals, uint256)` (fail-closed, view-only); zero/tiny collateral → `k_effective == 0` → revert. `A` is factory-bounded to [2, 10000] and `loan_discount` to ≤ 0.5 WAD, so the `unsafe_*` ops in `_get_k_effective` cannot overflow/underflow. No wrong-value path found.
- **Entry-point validation:** unknown Lend id reverts on DynArray OOB in `markets()`; unknown Mint id reverts on the first staticcall into the empty address (pinned — `_stash`'s empty-controller assert is defence in depth). `_N` bounds enforced by the controller after the callback (fail-late gas only, atomic). `_debt == 0` in `create_loan` reverts in `_calculate_debt_n1` (`assert _debt > 0`, controller.vy:502) — no zero-debt loan / locked collateral; `_debt == 0` in `borrow_more` is the controller's documented early-return no-op with full refund. Zero user collateral reverts on health (pinned).
- **Admin / kill-switch:** `set_exchange` checks the live factory admin each call and follows admin rotation (pinned). Delisting every exchange kills all zap flows (every entry path requires a whitelisted swap in its callback), so the documented kill procedure is complete; per-exchange delisting is one tx per compromised exchange.
- **Constants:** `EXCHANGE_CALLDATA_MAX_SIZE = 32000` and `CALLBACK_CALLDATA_MAX_SIZE = 32` are enforced by Vyper ABI decoding at the entry/callback boundary (at-max accepted, over-max reverts — pinned by `test_large_calldata.py`). The zap passes `b""` to the controller, so the controller's 9600-byte cap never binds aggregator routes.
- **Whitelisted exchange == controller/token/factory/zap:** requires admin misconfiguration (whitelist is admin-trusted; a whitelisted malicious exchange is excluded by the brief). Even then, the stash guard, shared lock, and controller pragma block fund movement: the exchange-as-controller shape cannot pass the callback lock/auth, and user calldata cannot spend the zap's controller allowances (spender-bound). Considered, not reportable under the brief's threat model.
- **Reentrancy via token hooks / malicious market tokens:** market tokens are factory-trusted setup; no zap-specific hook path exists beyond the standard ERC-20 assumptions the controller/AMM share. Considered, out of threat model.
